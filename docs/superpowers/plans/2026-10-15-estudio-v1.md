# Estúdio v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App web pessoal (PWA) para organizar, agendar, publicar e medir conteúdo de várias marcas em Instagram, TikTok e YouTube Shorts.

**Architecture:** Um único projeto Next.js (App Router, TypeScript) alojado na Vercel, com Supabase (Postgres + RLS, Auth, Storage, pg_cron/pg_net). As tarefas agendadas são rotas `/api/cron/*` chamadas pelo pg_cron. Cada rede é um `PlatformAdapter` com a mesma interface; a publicação é uma máquina de estados que avança um passo por tick.

**Tech Stack:** Node 22, Next.js 16, React, TypeScript, Tailwind CSS 4 + shadcn/ui, @supabase/supabase-js 2 + @supabase/ssr, zod, date-fns + date-fns-tz, tus-js-client, Vitest 4, pg (testes de BD contra Postgres 16 local), Playwright 1.56.1 (Chromium em `/opt/pw-browsers`).

**Spec:** `docs/superpowers/specs/2026-10-15-estudio-design.md`

## Global Constraints

- Toda a interface e todas as mensagens de erro para o utilizador em **português de Portugal** ("telemóvel", "carregar", "agendar").
- Datas guardadas em **UTC**; apresentadas e introduzidas no fuso da marca; fuso padrão de nova marca: `Africa/Maputo`.
- Tokens das redes: encriptados com AES-256-GCM (`TOKEN_ENC_KEY`, 32 bytes base64); **nunca** enviados ao browser nem incluídos em respostas de server actions.
- Rotas `/api/cron/*` exigem `Authorization: Bearer ${CRON_SECRET}`; sem ele → 401.
- Tamanho máximo de ficheiro: `NEXT_PUBLIC_MAX_UPLOAD_MB` (padrão **50**).
- Tentativas: falha temporária → nova tentativa após **1, 5, 15 min**; a 4.ª falha → `failed`. Esperas de processamento (contentor IG, TikTok, YouTube) não contam como tentativas; processamento > **30 min** → `failed`.
- Regras das redes (copiar exatamente para os validadores):
  - Instagram: imagens **só JPEG**; carrossel **2–10** itens; legenda ≤ **2200** caracteres; ≤ **30** hashtags; Reel 3 s–15 min; Story vídeo ≤ 60 s.
  - TikTok: vídeo 3 s–600 s; legenda guardada ≤ 2200 (não é enviada pela API no modo caixa de entrada).
  - YouTube Shorts: vídeo ≤ **180 s**, vertical ou quadrado (altura ≥ largura); título obrigatório ≤ **100**; descrição ≤ **5000**.
- Instagram: verificar `content_publishing_limit` antes de criar contentores; usar o `config.quota_total` devolvido (não fixar 100 nem 50).
- TikTok: modo caixa de entrada (`/v2/post/publish/inbox/video/init/`) com `FILE_UPLOAD`; nunca `PULL_FROM_URL`.
- YouTube: upload resumível com `privacyStatus: "private"`; quota contabilizada em `api_usage` com `YT_UPLOAD_UNITS` (padrão 1600) contra `YT_DAILY_UNITS` (padrão 10000); a quota reinicia à meia-noite `America/Los_Angeles`.
- Não publicar duas vezes o mesmo destino, nem com ticks sobrepostos nem após falha entre a publicação e a gravação na BD.
- Visual: azul-marinho `#0B1F45` e âmbar `#F0A93B` como cores base; cada marca tem a sua cor.
- Commits: mensagens terminam com as linhas de atribuição indicadas na sessão.

## Review Focus

1. **Foto HEIC e vídeo MOV do iPhone** carregados na biblioteca: HEIC é convertido para JPEG quando o browser o consegue descodificar (Safari); caso contrário, mensagem clara "Este formato não é suportado neste browser — exporte como JPEG". MOV é aceite. → teste na Task 15.
2. **Ticks sobrepostos ou queda entre `media_publish` e a gravação**: o destino não é publicado duas vezes (bloqueio `SKIP LOCKED` + recuperação do contentor `PUBLISHED`). → testes nas Tasks 3 e 8.
3. **Marca com horário de verão** (ex.: `Europe/Lisbon`): agendar 09:00 locais no dia da mudança de hora gera o instante UTC correto. → teste na Task 5.
4. **Conta com `needs_reauth` e posts devidos**: os destinos esperam (sem gastar tentativas) e retomam depois de religar. → testes nas Tasks 3 e 11.
5. **Apagar mídia ou conta usada por um post agendado**: bloqueado com mensagem clara, sem deixar posts órfãos. → testes nas Tasks 2 e 15.
